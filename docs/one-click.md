# 小白一键模式

## 目标

**不懂 ASR、不懂 CRF、不懂引擎区别的人，也能拿到字幕。**

设计原则：默认值必须对小白最优，高级选项折叠起来，出错时说人话。

## 三步

1. 拖入视频
2. 点「生成字幕」
3. 下载

没有第 4 步。

## 默认值为什么这么选

| 选项 | 默认 | 理由 |
|---|---|---|
| ASR 引擎 | `sherpa` | 27MB 依赖、0.1s 启动、带 token 时间戳。funasr 启动 31s（要加载标点模型），whisper 中文专名差且慢，jianying 是私有接口默认关闭 |
| 输出 | `soft`（软字幕） | **硬字幕会整片重编码**，实测 153MB 源片压到 3MB。小白不会意识到画质丢了。软字幕画质无损，播放器里能开关 |
| 质量 | `ultra` | 只有选 hard 时才生效；默认 soft 不受影响 |
| 翻译 | 不翻译 | 没配 LLM key 时翻译必然失败，默认开等于埋雷 |
| 语言 | 自动 | sense-voice 本身支持中英日韩粤自动判别 |

**关键取舍**：默认 `soft` 而不是 `hard`。
「烧进画面」听起来更符合直觉，但代价是整片重编码 —— 用户会以为工具把视频压坏了。
软字幕在 VLC/PotPlayer/浏览器里都能显示，对 90% 场景够用。

## 自动选引擎

前端按优先级挑第一个可用的：

```
sherpa → funasr → funasr-fast
```

**不自动选**：
- `whisper`：CPU 上 64s 音频要 39s，中文专名错得离谱（"DeepSeek" → "Deep Stick Hardness"）
- `jianying`：私有接口 + 第三方签名中转，可能随时失效，必须显式开启

## 修复的 bug：重复提交

截图里「上传中…」出现两遍 —— 点两下按钮就提交了两个任务。

原因：只在 `onclick` 里设 `disabled = true`，但 async 函数在第一个 `await` 之前
同步执行完，用户连点两下时第二次点击可能已经排队。

修法：加 `state.busy` 标志，进入即置位，`reset()` 才清除。

```js
if (state.busy) return;
state.busy = true;
```

## 后端也要有同样的默认值

前端传参只是"建议"，脚本/AI 直接调 API 时不会传这些字段。
所以 `server.py` 的 `Form(...)` 默认值必须和前端一致：

```python
asr_engine: str = Form("sherpa"),
burn_mode: str = Form("soft"),
```

**已验证**：只传 `{"path": "..."}`，零参数，5 秒出软字幕视频。

## 还能更傻瓜吗

现在的门槛：
- 要解压 zip；
- 要双击 exe；
- 首次转录要等 230MB 模型下载（5–8 分钟）。

可优化项（未做）：
